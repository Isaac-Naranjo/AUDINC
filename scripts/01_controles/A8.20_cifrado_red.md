# A8.20 Seguridad de redes — Cifrado nativo de red (NNE)

**PHVA:** Hacer · **Riesgo:** R-CONF-03 · **Tarea:** T-09 · **Verificación:** CO-15

> ✅ **Estado: APLICADO el 2026-10-15** (con aprobación del responsable). Respaldo del archivo original:
> `sqlnet.ora.antes_audinc`. Evidencia: la sesión PHP/OCI8 del evaluador muestra
> `AES256 Encryption service adapter` y `SHA256 Crypto-checksumming service adapter`; CO-15 = 0 hallazgos.
>
> Alcance: `sqlnet.ora` es de **toda la instancia XE**, así que el cifrado aplica a todas las conexiones de red,
> incluidas las de otros proyectos que usan esta instancia.

## Por qué
Sin cifrado de red, las consultas y los datos personales (Ley 8968) viajan en claro entre el cliente
(PHP, SQL Developer) y el listener: cualquiera que capture el tráfico puede leerlos.
Oracle Native Network Encryption cifra la sesión sin necesidad de certificados (a diferencia de TLS/TCPS).

## Archivo
`C:\app\isaac\product\21c\homes\OraDB21Home1\network\admin\sqlnet.ora`

## Procedimiento
1. Respaldar el archivo: `copy sqlnet.ora sqlnet.ora.antes_audinc`
2. Agregar al final:

   ```
   # AUDINC · A8.20 — cifrado y verificación de integridad obligatorios
   SQLNET.ENCRYPTION_SERVER = REQUIRED
   SQLNET.ENCRYPTION_TYPES_SERVER = (AES256)
   SQLNET.CRYPTO_CHECKSUM_SERVER = REQUIRED
   SQLNET.CRYPTO_CHECKSUM_TYPES_SERVER = (SHA256)
   ```

3. No requiere reiniciar: aplica a las **conexiones nuevas**.
4. Ejecutar una evaluación: CO-15 debe pasar a 0 hallazgos.

## Evidencia observable
```sql
SELECT network_service_banner
FROM   v$session_connect_info
WHERE  sid = SYS_CONTEXT('USERENV', 'SID');
-- Esperado: una línea "AES256 Encryption service adapter ..."
```

## Riesgo del cambio
Con `REQUIRED`, un cliente que no soporte NNE no podrá conectarse. PHP OCI8 (cliente 21.3) y SQL
Developer sí lo soportan. **Reversión:** restaurar `sqlnet.ora.antes_audinc`.
